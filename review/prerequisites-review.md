# Adversarial review — MISSING AND WEAK PREREQUISITES

**Reviewer:** adversarial pass, 2026-07-31. Target: `/home/claude/vcf-skills/skills/`.
**Rule under test:** every version-scoped reference file opens with `## Prerequisites` before any
endpoint; each item states (a) what must be true, (b) **how to verify it**, (c) the version it applies
to, (d) whether it exists in the other version; unverifiable prerequisites must be *stated as
unverified*, not omitted.

Method: structural audit of the six version-scoped files, then a backwards walk from **every** code
sample and worked example in all 19 skill files (bash/curl, PowerShell, kubectl, python, JSON bodies)
asking "what must already be true for this to succeed, and does the skill say so?", then a
cross-check against `research/foundation-auth-identity.md`, `research/nsx.md` and the shipped spec
inventory.

## 4. Notes on what is *not* a finding

- Both NSX files, both lifecycle files and both foundation files put `## Prerequisites` before the first
  endpoint, as required — no ordering violations.
- Every endpoint I spot-checked from a "How to verify" step resolves in the shipped spec inventory:
  `GET /v1/system`, `GET /v1/sddc-managers/{id}`, `GET /v1/version-drift` (9.1-only, correctly claimed),
  `GET /v1/sddc-manager/trusted-certificates`, `GET /suite-api/api/fleet-management/iam/{settings,ssorealms,vidbs,roles}`,
  `GET /api/v1/cluster/api-service`, `GET /policy/api/v1/infra/domains`, `GET /policy/api/v1/infra/services`.
  No fabricated verification endpoints found.
- The unverified-item discipline is otherwise strong: ports matrix, precheck enumeration, depot payload
  shape, orders 2–5 and 9–23, NSX 9.1 auth prose, VCF Automation All Apps token endpoint and VCF Installer
  auth are all stated as gaps rather than filled in.
